# 等级升级说明（封存档）

- 定稿日期：2026-11-19（升级当天封档，此后不许改口本专册）
- 适用仓：06-lagboard 源到达SLA
- 状态：**已封存 · 定稿**

## 1. 唯一正确性口径

等级升级只能走「告警升违约连坐改态账本」这一种。本仓不存在第二条升级口径，采集侧的滞后分级仅作对照，不承担升级。

- 仅许可既有到达 `告警 -> 违约` 的升级；对违约/正常到达发起升级、对同一到达重复升级，一律判 **升级偏了**，驳回（HTTP 409）并在升级专册留痕，正式零改。
- 升级必须是真实写路径：改到达等级、连坐改源输出态（降级只读 -> 冻结）、写升级账本。严禁只改徽章颜色；严禁弄丢到达主键（`arrivals.id` 全程透传并回显）。
- 偏离本说明即驳回，并在账本留下 `升级偏了`。

## 2. 路径择一：甲、乙不得混用

本仓定稿采用 **甲路径**。乙路径（先落升级意图再派生提交输出态、失败则意图作废）**不采用、不实现**，两路严禁混用。

### 甲路径（本仓唯一实现）

违约等级与源输出态**同库一次提交**（同一 SQLite 事务）：

1. 占该源的升级锁（见第 4 节）；
2. 同一事务内三笔写：
   - `UPDATE arrivals SET level='违约'`（按到达主键定位）；
   - `UPDATE sources SET output_mode='冻结'`（连坐改态，源目录不再停留降级只读）；
   - 向 `upgrade_ledger` 写一条 `成功` 账本；
3. 一次 `commit`；
4. 任一笔写遇错则 `rollback` **全部撤回**，等级、目录态、账本正式零改，接口返回 500「等级升级失败，已全部撤回」；
5. finally 释放升级锁。

不存在意图表、不存在分步提交；升级结果只有「整笔成功」或「整笔零改」两种。

## 3. 入口与口令

- 分级入口挂在前端「滞后分级」页（策略附页）内，**不另起升级台**。
- 口令沿用本仓登录侧：升级接口走既有 Bearer 会话（`/api/login` 签发，admin/123456 等既有账号），未登录返回 401，不新增认证体系。
- 库文件沿用本仓升级仓区：全部落 `data/app.db`（SQLite，随 `data/` 卷持久化），不挂外置库。

## 4. 升级锁与双路争用

- 值班双路同时点同一源升级，必须先占升级锁；锁粒度为源。
- 实现：进程内每源一把非阻塞锁（`upgrade_locks` 字典），另有持久表 `upgrade_locks(source PK)` 在同库留痕，跨进程亦互斥。
- 后交者拿不到锁：**不做任何改态**，只在 `upgrade_ledger` 记一条 `等级升级争用`（含后交操作人与时间），接口返回 409。
- 锁在请求结束（含异常）后必然释放，不留残留。

## 5. 五处同态可读

升级后以下五处读取同一套库数据，状态必须同态：

| 视图 | 位置 | 同态内容 |
|----|----|----|
| 到达详情 | 「到达登记」时间线 | 到达主键 id、等级（违约） |
| 源目录 | 左侧源卡 | 源输出态（冻结） |
| 策略附页 | 「滞后分级」页 | 等级与输出态、升级按钮留痕 |
| 水位卡片 | 顶部统计卡 | 冻结/降级/升级留痕计数 |
| 审计列表 | 「升级审计」页 | upgrade_ledger 全量（成功/争用/升级偏了） |

只改徽章颜色而库态未变，判升级未过。

## 6. 账本与表结构

`upgrade_ledger`（升级专册）：

| 列 | 含义 |
|----|----|
| id | 账本主键 |
| arrival_id | 到达主键（禁止丢失） |
| source | 源名称 |
| from_level / to_level | 改态前后等级 |
| result | `成功` / `等级升级争用` / `升级偏了` |
| note | 操作人、理由与路径标注 |
| created_at | ISO 时间戳 |

`upgrade_locks`：`source` 主键 + holder + created_at，仅在升级进行中持有行，结束即删。

## 7. 接口

- `POST /api/arrivals/{arrival_id}/upgrade`：告警升违约（甲路径）。200 成功；409 争用或升级偏了；404 到达不存在；401 未登录；500 事务失败已全撤回。
- `GET /api/upgrade-ledger`：升级专册列表（倒序）。
